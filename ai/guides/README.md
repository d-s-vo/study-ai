# Guides — практические руководства для AI-ассистента

> Эта папка содержит **процессные гайды**: как разрабатывать фичи и как работать со стеком проекта.
> **Перед стартом нетривиальной работы** — читай нужный файл. Точка входа любой задачи — `../architecture.md` §0 (роутер).

Если нужна **архитектура** (что из чего состоит) — `../architecture.md`.
Если нужно **что уже сделано** — `../memory.md`.

---

## Содержание (базовое)

| Файл | Когда читать |
|------|--------------|
| `./feature-workflow.md` | **Обязательно** для любой нетривиальной фичи: spec → тройная проверка → тесты → реализация → impl.md → коммит-ревью |
| `./adr-execution.md` | Крупный блок (десятки фич), когда ты — **оркестратор**: делегирование фич субагентам + живой документ ADR. Слой НАД `feature-workflow.md` |
| `./commit-review.md` | Независимое по-коммитное ревью (ADR-010): ты — ревьюер (не автор), рубрика по существу diff, вердикт FAIL=veto |
| `./debugging.md` | Тест упал / данные пропали / рендер пуст и **причина неясна**: playbook поиска root-cause |
| `./live-acceptance.md` | **Живая приёмка**: проверить X живьём (curl / браузер / e2e), а не только зелёные тесты. Часть DoD |
| `./stack-specifics.md` | **Стек-специфика проекта** (команды гейтов, venv, env-адреса, инварианты, сквозные реестры). Сюда ведут все `# ADAPT:` из других гайдов |
| `./coordination.md` | **Параллельная работа нескольких агентов** в одном workspace: брони фич, изоляция окружений, гейт-локи, presence. Читать до старта, если агентов >1 (и для изолированного стенда даже соло) |
| 
| `./process-retro.md` | *(опционально)* Ретро **процесса** (не продукта) при закрытии инициативы: что стоило дорого, что переделали |
| `./briefs/` | Тонкие преамбулы-роли для делегирования (`executor.md`, `sidecar-verifier.md`, `track-orchestrator.md`, `commit-reviewer.md`); канон процесса — в гайдах, брифы лишь указывают |

**Дополнительные проектные гайды** (создавать по мере роста, вынося из `stack-specifics.md`):
`api-service.md` (серверная сущность/endpoint), `client-entity.md` (клиентская сущность),
`dev-local.md` (локальный стенд — пока живёт в `../ops/local-setup.md`), `deploy.md` (доставка).
Принцип: `stack-specifics.md` — отправная точка, дробить по мере роста, оставляя там навигацию.
