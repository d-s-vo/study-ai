# Briefs — тонкие преамбулы для агентов-ролей

> **Что это.** Короткие преамбулы-указатели для субагентов, которых запускает оркестратор крупной инициативы ([`../adr-execution.md`](../adr-execution.md)). Каждый бриф — **тонкий указатель**, а не второй канон: он напоминает роль и порядок чтения, но полный процесс живёт в основных гайдах. Не дублируй сюда содержимое `feature-workflow.md` / `adr-execution.md`.

> **Когда нужны.** Только при делегированном исполнении (оркестратор + субагенты). Для одиночной фичи брифы не нужны — работаешь напрямую по [`../feature-workflow.md`](../feature-workflow.md).

## Какому агенту какой бриф

| Роль агента | Бриф | Суть |
|---|---|---|
| **Исполнитель одной фичи** | [`executor.md`](executor.md) | Реализует ОДНУ фичу в своём worktree по `feature-workflow.md`, возвращает сжатую сводку |
| **Независимый проверяющий** | [`sidecar-verifier.md`](sidecar-verifier.md) | Адверсариально проверяет (ревью / безопасность / согласованность), возвращает `Verdict: PASS\|WARN\|FAIL` |
| **Ревьюер коммитов** | [`commit-reviewer.md`](commit-reviewer.md) | Независимое по-коммитное ревью (ADR-010) по `commit-review.md`; ревьюер ≠ автор |
| **Трек-оркестратор** | [`track-orchestrator.md`](track-orchestrator.md) | Ведёт таблицу инициативы, делегирует, сам код НЕ пишет; merge только через него |

## Общий принцип возврата

Все брифы разделяют одно правило: **агент возвращает оркестратору ДАННЫЕ, а не сообщение пользователю.** Сводка сжатая (дельта состояния, не пересказ протокола) — оркестратор держит в контексте выводы, а не сырой ход работы.
