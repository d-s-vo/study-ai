# Infrastructure — серверная инфраструктура проекта (модуль M8)

**Статус:** не задокументировано. Заполняется по мере появления/выяснения инфраструктуры клиента —
не выдумывать заранее.

## Назначение

Актуальная информация о серверах, доменах и shared-ресурсах проекта. Используется агентом и людьми
для быстрого доступа к инфраструктурной информации, когда она вообще есть и относится к нашей зоне
ответственности (в отличие от локального стенда разработки — тот в `../ops/local-setup.md`).

## Структура

```
ai/infra/
├── README.md              # Этот файл
├── domains.md              # Домены, DNS, routing, SSL
└── servers/
    └── <hostname>.md      # Карточка каждого сервера
```

## Соглашения

### Серверы
- Каждый сервер = один `.md` файл в `servers/`.
- Имя файла = hostname / SSH alias (kebab-case).
- Карточка содержит: ОС, ресурсы, установленное ПО, порты, процесс-менеджер (systemd/PM2/Docker).
- **Секреты НЕ хранятся** — только ссылки на `.env` файлы / secret-storage.

### Домены
- Все домены и subdomains документированы в `domains.md`.
- Включает: DNS-записи, routing, SSL статус.

### Обновление
- После любых изменений на сервере → обновить карточку сервера.
- После добавления/изменения домена → обновить `domains.md`.
- После изменения процесса деплоя → обновить соответствующий гайд в `../guides/`.

## Границы (что здесь НЕ ведём)

Если прод/деплоймент клиента находится под управлением другой команды/системы (read-only для нас) —
карточки таких серверов сюда не заводятся; фиксируется только обзорный статус и ссылка на
первоисточник.
