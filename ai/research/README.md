# Research notes

Место для исследовательских заметок, экспериментов, анализа библиотек/подходов.
Каждое исследование — **отдельная подпапка** `NNN-тема/` (например `001-выбор-очереди/`)
с `README.md` внутри. Отдельные `.md`-файлы в корне `research/` запрещены (кроме этого README).

Заметки НЕ являются архитектурными решениями (это `../adr/`) и НЕ являются фичами (это `../devlog/features/`).

## Когда использовать

- Изучение новой библиотеки/подхода перед интеграцией (плюсы/минусы, альтернативы).
- Проверка гипотезы (proof-of-concept, временные эксперименты).
- Анализ существующего кода («как работает X в подсистеме Y»).
- Заметки по поводу чужих проектов / opensource-инструментов.

## Формат (обязательный)

- Каждое исследование — подпапка `NNN-тема/`: `NNN` — трёхзначный порядковый номер (`001`, `002`, …),
  следующий за максимальным существующим; `тема` — короткий kebab-case-слаг.
- Внутри подпапки — обязательный `README.md` (точка входа: цель, выводы, статус); остальные
  файлы/подпапки — свободно, по необходимости.
- Номера не переиспользуются: если исследование удалено/закрыто, его номер остаётся занятым.
- Перед созданием проверь существующие номера: `ls ai/research/` — и возьми следующий.

Содержание внутри темы — свободное. Полезный паттерн для содержательных исследований (не обязателен
для коротких заметок): нумерованные шаги внутри темы, явные verification-факты (что реально проверено
командой/запуском, а не предположено), адверсариальный проход по собственным выводам перед конверсией
в ADR.

## Связь с другими разделами

- Если исследование **привело к архитектурному решению** → оформи ADR в `../adr/` со ссылкой на research-заметку.
- Если исследование **превратилось в реализацию** → оформи фичу в `../devlog/features/FEAT-NNN-*/` со ссылкой на research.
