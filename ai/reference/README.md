# ai/reference/ — самодостаточные справки (модуль M9)

Standalone-справки под конкретный профиль команды — не методология (это `ai/guides/`), не
архитектурное решение (это `ai/adr/`), не журнал фичи (это `ai/devlog/`). Жанр: «стек/паттерн глазами
разработчика с другим бэкграундом» или любая другая самодостаточная выжимка знания, которая иначе
терялась бы в чатах/головах.

## Когда заводить файл сюда

- Команда/агенты систематически спотыкаются об один и тот же класс непонимания (стек, парадигма,
  нестандартный паттерн проекта) — вместо повторного объяснения в каждой фиче пишется одна
  справка, на которую все ссылаются.
- Справка **не привязана к конкретной фиче** и не устаревает вместе с кодом так же быстро, как
  `impl.md` — иначе её место в `devlog/`.

## Формат

Свободный, один файл на тему, `kebab-case-slug.md`. Справка должна быть читаема самостоятельно, без
контекста остальной `ai/` — это её отличие от гайдов (которые предполагают, что читатель уже знает
роутер `architecture.md` §0).

## Связи

- [`../architecture.md`](../architecture.md) — если справка объясняет предпосылку архитектурного
  решения, решение всё равно фиксируется в `../adr/`, а не здесь.
- [`../guides/README.md`](../guides/README.md) — методология (процесс), в отличие от справки (знание).
