# cbook@7965bbd — раздел пользователей в админ-панели (только чтение)

> Коммит-сообщение (как в клиентском репо): `feat: раздел пользователей в админ-панели (только чтение)`

## Кратко (для инженера)

- `app/Filament/Resources/Users/UserResource.php` — `$model = User::class`; `canCreate()`/`canEdit()`/`canDelete()` жёстко возвращают `false` — управление учётками полностью выключено на уровне Resource, не только скрыто в UI. `getPages()` содержит только `index` и `view` (нет `create`/`edit` — соответствующих Page-классов и формы в проекте нет вовсе). `getEloquentQuery()` добавляет `withCount('recipes')` — счётчик рецептов пользователя одним запросом, без N+1 в таблице.
- `app/Filament/Resources/Users/Tables/UsersTable.php` — колонки: `id`, `name`, `email`, `email_verified_at`, `is_admin` (через `IconColumn::boolean()`), `recipes_count`, `created_at`; единственное действие записи — `ViewAction` (просмотр).
- `app/Filament/Resources/Users/Schemas/UserInfolist.php` — те же поля в режиме "только для чтения" (Infolist, а не форма) для страницы просмотра.
- `app/Filament/Resources/Users/Pages/{ListUsers,ViewUser}.php` — минимальные, без переопределений (просто указывают `$resource`).
- Нигде — ни в таблице, ни в infolist — не выводятся `password` или `remember_token`.

## Детально (для новичка)

### Зачем это всё: полезный просмотр без сенситивной поверхности

Спека фичи разделяет два раздела админки принципиально по-разному: рецепты — полноценный CRUD (следующий коммит), пользователи — только просмотр. Причина не техническая, а продуктовая/защитная: администратору полезно видеть, кто зарегистрирован и сколько у кого рецептов (например, для модерации), но управление самими учётками — сброс пароля, смена почты, удаление аккаунта — операции с последствиями для реального человека, которые в этой итерации сознательно не автоматизируются через UI.

### `canCreate`/`canEdit`/`canDelete` → `false` — это не только "спрятать кнопку"

В Filament эти методы `Resource` — не косметика поверх таблицы, а точка, которую фреймворк сам спрашивает перед тем как зарегистрировать соответствующие маршруты/действия. Если бы они не были переопределены, `Resource` по умолчанию сгенерировал бы create/edit-страницы автоматически (так же, как это происходит для `RecipeResource`). Явный `false` — тот же приём, что и `getPages()` без ключей `create`/`edit`: даже если кто-то по ошибке попытается обратиться к `/admin/users/{id}/edit` напрямую, соответствующего маршрута просто не существует — это защита на уровне регистрации маршрутов, а не только скрытая в интерфейсе кнопка.

### Почему нет `UserForm` и почему это не половина фичи

В `RecipeResource` (следующий коммит) форма — центральный артефакт: через неё создают/редактируют. Здесь формы create/edit не существует вовсе, потому что нет соответствующих Page-классов, которые бы её использовали (`ListUsers`/`ViewUser` — единственные страницы). Это не "недоделанный CRUD", а осознанно read-only ресурс — сокращённый до нужного минимума, а не CRUD с урезанными правами поверх.

### Чувствительные поля и `withCount`

`UsersTable`/`UserInfolist` перечисляют ровно те поля, которые нужны для просмотра: идентификация (`id`/`name`/`email`), статус (`email_verified_at`, `is_admin` как иконка через `IconColumn::boolean()`), активность (`recipes_count`, `created_at`). `password` (хеш) и `remember_token` нигде не упоминаются — их физически негде увидеть в панели, это не "скрыто стилями", поле просто не запрошено и не отрендерено. `recipes_count` — вычисляемый агрегат, а не колонка таблицы `users`; чтобы Filament мог его показать без N+1 (отдельный запрос `COUNT(*)` на каждую строку таблицы), `getEloquentQuery()` заранее подмешивает `withCount('recipes')` в базовый запрос — Eloquent сам добавляет `recipes_count` как виртуальный атрибут одним JOIN-подзапросом.

## Почему так, а не иначе

- **`canCreate/canEdit/canDelete → false` вместо просто отсутствия страниц в `getPages()`** — оба слоя защиты оставлены намеренно избыточными: `getPages()` без create/edit убирает сами маршруты, `can*` методы дополнительно убирают кнопки действий и любые программные пути вызова (например, bulk actions), которые Filament мог бы сгенерировать независимо от списка страниц.
- **`IconColumn::boolean()` для `is_admin` вместо текстовой колонки** — стандартный компонент Filament для булевых полей, читается как иконка (галочка/крестик) быстрее, чем текст `"1"/"0"` или `"true"/"false"`.
