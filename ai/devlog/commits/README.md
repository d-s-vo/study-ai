# Per-commit rationale — разборы «почему» клиентских коммитов

Детальный разбор каждого коммита агента в клиентский репо (`cbook`).
Решение и обоснование — [`../../adr/009-per-commit-rationale.md`](../../adr/009-per-commit-rationale.md).

> Зачем: если включён режим секретности (`architecture.md` §8, модуль M6), в клиентском коммите
> нельзя раскрывать «почему» сделано именно так. Этот слой живёт **только в `study-cbook-ai`** и
> отвечает на вопрос стороннего разработчика «почему сделано именно так» — понятно **даже
> новичку**. Уровень коммита (мельче фичи/ADR): **ссылается** на `impl.md`/`spec.md`/ADR, не
> дублирует их. При M6=OFF слой остаётся ценен как audit-trail (см. M-note в `docs/module-matrix.md`
> шаблона), просто перестаёт быть единственным местом «почему».

## Раскладка

```
ai/devlog/commits/
├── README.md                 # этот файл (конвенция + два реестра: разборов и ревью)
├── _template.md               # шаблон разбора «почему» (ADR-009, копировать)
├── _review-template.md        # шаблон review-файла (ADR-010, копировать)
└── <repo>/                    # одно из cbook
    ├── <short-hash>-<slug>.md    # разбор «почему» (автор, ADR-009)
    └── <short-hash>-review.md    # вердикт ревью (независимый ревьюер, ADR-010)
```

- `<repo>` — имя клиентского репо.
- `<short-hash>` — короткий SHA коммита на ветке `feat/<slug>` **в момент создания**
  (as-authored), не финальный клиентский хеш (тот меняется при squash/rebase MR — см. ниже).
- `<slug>` — короткий смысл коммита латиницей (kebab-case).

**Шардинг (на будущее):** пока раскладка плоская по репо. Если в одном репо накопится ~500–1000
файлов — вводится один уровень шарда по первым 2 символам short-hash (`<repo>/ab/abcdef1-slug.md`).
До этого порога — не усложнять.

## Устойчивость ключа (squash/rebase MR)

Агент коммитит на `feat/<slug>` локально; человек мержит MR в `develop`.
Squash/rebase **меняет SHA** (squash уничтожает исходные хеши). Поэтому:

- **Имя файла и ключ — as-authored short-hash** (наш, стабильный). Файл при squash/rebase **не
  переименовывается**.
- В шапке файла дублируются устойчивые якоря: as-authored **full hash**, `git patch-id` (хеш от
  diff — переживает rebase), ветка, `FEAT-NNN`, дата.
- Финальный клиентский хеш — **колонка «итоговый хеш»** в реестре ниже, заполняется best-effort при
  обнаружении (не обязателен в момент написания разбора).

```bash
# patch-id для шапки (from-worktree клиентского репо):
git show <hash> | git patch-id --stable
```

## Процесс

1. Агент-исполнитель фичи пишет разбор **сразу после каждого клиентского коммита** (или пачкой в
   конце фичи, до сводки оркестратору), копируя `_template.md`.
2. Коммит разбора — в `study-cbook-ai` через `scripts/ai-commit.sh "<msg>" <пути>` (это артефакт
   `study-cbook-ai`, НЕ клиентский код — не через `scripts/commit.sh`).
3. Добавить строку в реестр ниже (**append-only**, не переписывать чужие строки).
4. Оркестратор проверяет наличие разборов при приёмке фичи (`../../guides/adr-execution.md` B.2).

## Ревью коммитов (ADR-010)

Разбор «почему» (выше) пишет **автор** и не содержит вердикта. Отдельно каждый клиентский коммит
проходит **обязательное независимое ревью** самого diff по существу — его делает **другой агент**
(ревьюер, модель для сложного/ревью). Решение — [`../../adr/010-mandatory-commit-review.md`](../../adr/010-mandatory-commit-review.md);
операционный гайд ревьюеру — [`../../guides/commit-review.md`](../../guides/commit-review.md); шаблон
вердикта — [`_review-template.md`](_review-template.md).

**Двухуровневая модель трекинга:**

- **Источник истины — file-per-object:** отдельный `ai/devlog/commits/<repo>/<short-hash>-review.md`
  рядом с разбором. Пишет **только ревьюер**, не трогая файл-разбор автора. Ключ — тот же
  as-authored short-hash. Разные коммиты → разные файлы → параллельные ревьюеры не конфликтуют.
- **Реестр ревью ниже — вторичная витрина/индекс** для человека (быстрый взгляд «что в каком
  статусе»). Гейт покрытия по нему **НЕ считается** — реестры вторичны и могут отставать от файлов.
  Правится **под локом `scripts/edit-shared.sh`** (append-в-конец, чужие строки не трогать).

**Правило вычисления «непроверенных»** (машинно, race-free — это же и гейт merge) — канон и точная
формула зафиксированы в [`../../guides/commit-review.md`](../../guides/commit-review.md) §9;
здесь не дублируется, чтобы не разойтись при правках. Кратко: считается **по review-файлам**
(файловая система), НЕ по реестру ниже — реестр лишь быстрая витрина для взгляда человека.
