# ADR-010: Обязательное независимое ревью каждого клиентского коммита (mandatory per-commit review)

**Статус:** Принят (системный ADR шаблона) — **НЕотключаемое ядро качества**

> Системный ADR методологии. Ревью коммитов **не отключается ни в одном профиле** — это несущий инвариант
> качества AI-кода (плотность дефектов AI-кода ×1.4–1.7 к человеческому). Операционная инструкция —
> [`../guides/commit-review.md`](../guides/commit-review.md). При развёртывании: подставь имена скриптов/репо
> и `Dmitriy` для эскалации.

## Контекст

Между «коммит создан» и «merge в интеграционную ветку» образуется **дыра**: нет обязательной независимой
проверки самого diff по существу. Существующие точки покрывают другое:

- тройная проверка spec (feature-workflow Шаг 5) — ревью **дизайна ДО кода**, не реализации;
- минимальный набор автоматических гейтов (тесты/typecheck/lint) — **автоматика**, семантику не читает;
- разбор «почему» (ADR-009) — **rationale тем же автором**, без вердикта PASS/FAIL;
- «ревью чистоты» (Шаг 12) — узкий скоуп «следы системы», не корректность;
- приёмка оркестратором (B.2) — дословно «не открывая код»;
- финальная приёмка инициативы (Часть D) — на всю инициативу, слишком поздно и крупно;
- sidecar-верификатор (Часть C) — опция, не обязанность.

Научная рамка: плаузибельность ≠ корректность; «near-miss syndrome» AI-кода не даёт человеческих сигналов
дефекта; самый трудный класс — код, проходящий happy-path, но не соответствующий *интенту* спеки. AI-код даёт
~1.4–1.7× больше critical/major находок → проверять надо **каждый** коммит, не выборочно.

Требование владельца: (1) КАЖДЫЙ коммит перепроверяется ОТДЕЛЬНЫМ агентом (не автором) ПОСЛЕ коммита и ДО merge;
(2) аудируемый трекинг «проверен/вердикт/закрыт», непроверенные видны; (3) минимизация техдолга при закрытии
находок; (4) работа при параллельных агентах без конфликтов; (5) перед merge — все коммиты проверены и закрыты.

## Рассмотренные и отвергнутые варианты (сохранены как обоснование)

- **Advisory-only ревью** (не блокирует merge) — отвергнут: нужен blocking-гейт до merge.
- **Единый вердикт-на-фичу** — отвергнут: ломает «1 коммит = 1 ревью-единица» и наглядность реестра.
- **Вердикт-секция внутри файла-разбора ADR-009** — отвергнут: гонка автор↔ревьюер за один файл, смешение ролей.
- **Правка ячейки вердикта в чужой строке реестра** — отвергнут: нарушает append-only. Взято только «общий
  реестр как витрина».
- **git notes для статуса** — отвергнут: осиротение при rebase/squash.
- **Отдельный verifier на КАЖДУЮ находку всегда** — отвергнут: дорого; заменено «Evidence обязательна везде +
  fan-out на high-stakes».
- **Обязательный мутационный прогон на каждый коммит** — отвергнут: тяжело per-commit; берём мутационное
  *мышление* как пункт рубрики.
- **Изоляция ревьюера без доступа к `ai/`** — отвергнут: ему нужен spec/keystone как якорь интента (без-`ai/`
  изоляция — только детектору следов, Шаг 12).
- **Hash-chaining ledger трекинга** — отвергнут: overkill для доверенного приватного репо.

## Решение

Вводится **обязательное независимое по-коммитное ревью**. Полная инструкция —
[`../guides/commit-review.md`](../guides/commit-review.md); ниже — несущие решения.

**1. Скоуп и якорь.** Ревьюер ≠ автор (свежая модель пытается опровергнуть результат; self-review LLM ведёт к
collapse). Якорь ревью — **спека/интент**; поэтому ревьюер, в отличие от «ревью чистоты», **имеет доступ к `ai/`**.
Рубрика: атомарность коммита (первичный gate ревьюабельности) · логика-vs-спека · business-security (OWASP) ·
тихие регрессии/parity · качество тестов мутационным мышлением · перф · over-engineering. Тривиальный коммит
(doc-only/косметика) — сокращённая рубрика с пометкой `trivial-scope`; классифицирует **ревьюер**, не автор.

**2. Запуск.** После коммита и ДО merge. В **оркестрированном режиме** ревьюера запускает оркестратор; в
**соло-режиме** соло-исполнитель **обязан** запустить свежий субагент-ревьюер с чистым контекстом. Модель
ревьюера — `Opus 4.8`. Ревьюер НЕ мержит и не трогает git-состояние.

**3. Анти-соглашательство.** Обязательные **негативные критерии** («найди вход, где сломается»; «докажи, что
тест НЕ вакуумный»). Блокировать — **только по подтверждённой Evidence** (file:line + контрпример); голый
вердикт не блокирует. Для high-stakes (`аутентификация/сессии (Laravel auth), файловое хранилище (S3/MinIO), доступ к БД (Eloquent + репозиторный слой), Filament-панель (политики доступа)`) — fan-out отдельным верификатором на blocker.

**4. Вердикты и эскалация.** Формат — расширение канонического sidecar-контракта (`adr-execution.md` Часть C):
`PASS | WARN | FAIL`, Verdict в первых 5 строках, Blocking findings с Evidence, `Suggested next`. Маппинг
severity→вердикт→merge: **FAIL** (blocker/major) = veto, merge запрещён; **WARN** (minor) = advisory, закрыть
или принять с записью; **nit** не блокирует; **PASS** = разрешён. Два независимых сигнала: вердикт ревьюера
`Code-Review` и зелёный минимальный набор гейтов (тесты/typecheck/lint); FAIL любого блокирует merge. **FAIL-veto снимает ТОЛЬКО сам ревьюер**;
оркестратор не переопределяет молча; неразрешимое несогласие → **эскалация владельцу `Dmitriy`**.

**5. Трекинг (двухуровневый).**
- **Источник истины — file-per-object:** отдельный файл-вердикт `ai/devlog/commits/<repo>/<short-hash>-review.md`
  рядом с разбором ADR-009. Пишет **только ревьюер**, не трогая файл-разбор автора. Ключ — as-authored short-hash.
- **Реестр ревью — вторичная витрина:** append-only таблица в `ai/devlog/commits/README.md`, правится **под
  локом `edit-shared.sh`**.
- **«Непроверенные» (машинно, race-free):** `{коммиты git log base..<branch>}` **∖** `{коммиты с
  <hash>-review.md: вердикт PASS/WARN и blocker закрыты}`. Гейт считается **по review-файлам**, не по реестру.

**6. Политика находок.** FAIL/blocker → фикс-коммит исполнителем ДО merge. **Фикс — цикл `feature-workflow.md`
соразмерно масштабу** (тест-first red→green, гейты, `commit.sh`, разбор ADR-009); контракт меняется → сначала
спека (+keystone-дельта); крупный фикс → фикс-фича `FEAT-NNN.a`. **Цикл замыкается ревью** каждого фикс-коммита;
«тихий» фикс без разбора и ревью = непроверенный коммит, ловится гейтом покрытия. fix-forward — только с
задокументированным адресом. Планка — Google «изменение определённо улучшает здоровье кодовой базы», не совершенство.

## Последствия

- **Новый шаг DoD.** Фича не принимается, пока каждый её коммит не имеет review-файла PASS/WARN с закрытыми
  blocker. Пропуск ловит оркестратор (B.2) и переинвентаризация перед merge (H.2).
- **Стоимость** — порядка одного `Opus 4.8`-ревью на коммит (при батче — 1 запуск на пачку с N вердиктами).
- **Ноль следов сохраняется** (режим секретности M6 включён): механика ревью — артефакт `ai/` (коммит через `ai-commit.sh`).
- **Независимость держится структурно** — отдельным субагентом, не «сменой шляпы».
