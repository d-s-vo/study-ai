# ADR-006: Миграция cbook с Nuxt 4 на Laravel (brownfield)

**Статус:** Принят (зафиксирован при инициализации `ai/`)
**Дата:** 2026-07-28

> Продуктовый decision-ADR, brownfield. Фиксирует намерение и последствия миграции — без выдуманного
> обоснования: описано фактическое решение, принятое при инициализации базы знаний.

## Контекст

Действующее приложение cbook написано на Nuxt 4 (Vue 3 / TypeScript) с Prisma + PostgreSQL (Neon), хранением изображений в MinIO (S3) и внешним доступом через Cloudflare Tunnel. Принято решение перевести проект на целевой стек Laravel 11 + Filament + Inertia/Vue (ADR-002) со слоистой архитектурой (ADR-003). Миграция идёт **в том же клиентском репозитории** `cbook`; это первая крупная инициатива проекта.

## Рассмотренные варианты

### Вариант А — Продолжать развитие на Nuxt, не мигрировать
- **За:** нет стоимости переноса; код уже работает.
- **Против:** отклонён на уровне выбора стека (ADR-002) — нужна «батарейная» серверная экосистема и готовая админка Filament.

### Вариант Б — Миграция на Laravel (выбран)
- **За:** целевой стек из ADR-002; переиспользование Vue 3/TS на фронте через Inertia; PostgreSQL сохраняется (преемственность с Neon).
- **Против:** brownfield-перенос — сосуществование двух контуров на время миграции; риск для данных/поведения; объём работы.

> История первичного выбора Nuxt не восстанавливается; здесь фиксируется решение перейти на Laravel как факт текущего состояния.

## Решение

1. **Миграция — первая крупная инициатива** проекта; вести по [`../guides/adr-execution.md`](../guides/adr-execution.md) (оркестратор + субагенты по фичам), либо пофично по feature-workflow — по мере уточнения объёма.
2. **Данные:** PostgreSQL сохраняется как СУБД; схема переносится под **Laravel-миграции** (`database/migrations/`), а не Prisma. Исторические Prisma-миграции напрямую не применимы — схема воспроизводится заново под Eloquent (см. Gotcha «Neon → Sail Postgres» в `../memory.md`).
3. **Файлы:** изображения рецептов — через файловый драйвер `s3` Laravel Storage; MinIO/S3 сохраняется как хранилище.
4. **Сущности** (Recipe, Ingredient, Step, Category, User) переносятся в слоистую модель (ADR-003): миграция → Eloquent/репозиторий → Domain → сервис → HTTP/Inertia + Policy → тесты.
5. **Сосуществование контуров:** до завершения миграции legacy Nuxt-контур (Prisma/Neon/MinIO/Cloudflare Tunnel) существует параллельно; переключение — по готовности.
6. **process-retro (M7)** включается при старте этой инициативы (см. `../memory.md`).

## Последствия

- Появляется параллельный legacy-контур на время миграции; боевые креды обоих контуров из `.env` наружу не выносятся, в тестах не используются (тесты — на `.env.testing`).
- Перенос сущностей подчиняется инвариантам слоёв (ADR-003) и порядку создания сущности из [`../guides/stack-specifics.md`](../guides/stack-specifics.md).
- Grabli переноса (несовместимость Prisma↔Laravel-миграций, S3-драйвер, туннель) фиксируются в `../memory.md` §Gotchas по мере набивания.
- Открытые вопросы к владельцу: финальная СУБД (Postgres по умолчанию), нужен ли Cloudflare Tunnel при Sail-стенде, статус CI на `develop`.
