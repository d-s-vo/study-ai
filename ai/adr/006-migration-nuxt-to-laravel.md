# ADR-006: Переписывание cbook на Laravel (учебная инициатива, greenfield)

**Статус:** Принят (зафиксирован при инициализации `ai/`; рамка уточнена под ТЗ заказчика)
**Дата:** 2026-07-28

> Продуктовый decision-ADR. Фиксирует намерение и последствия **переписывания cbook с нуля** на целевом
> стеке ради обучения — без выдуманного обоснования: описано фактическое решение, принятое при инициализации
> базы знаний, с учётом уточнённой рамки (см. `PROJECT-BRIEF.md`).

## Контекст

Легаси-приложение cbook написано на Nuxt 4 (Vue 3 / TypeScript) с Prisma + PostgreSQL (Neon), хранением изображений в MinIO (S3) и внешним доступом через Cloudflare Tunnel. Стек Nuxt/Prisma **списан** — он больше не развивается.

Настоящая цель инициативы — **обучение**: владелец осваивает сборку и сопровождение **enterprise-монолитов на Laravel** в стиле своих референс-проектов `listvafintess` и `av1` (их конкретные конвенции в этой базе знаний не задокументированы — не выдумывать, при необходимости спрашивать владельца). Учебный проект cbook — **подопытный кролик** для отработки паттернов, а не продукт, который надо сохранить или точно перенести.

Поэтому это **переписывание с нуля (greenfield)**, а НЕ миграция и НЕ порт Nuxt-кода 1:1. Целевой стек — Laravel 12 + Filament + Inertia/Vue (ADR-002) со строгой слоистой архитектурой Task/Repository/DTO/Resolver (ADR-003). Работа идёт **в том же клиентском репозитории** `cbook`, где сейчас лежит только legacy Nuxt-код (Laravel-проекта ещё НЕТ: нет `composer.json`, `artisan`, `vendor/`; каталог `app/` занят Nuxt-фронтом — коллизия с бэкендом Laravel). Это первая крупная инициатива проекта.

## Рассмотренные варианты

### Вариант А — Продолжать развитие на Nuxt, не переписывать
- **За:** нет стоимости переписывания; код уже работает.
- **Против:** не решает учебную цель — владелец хочет осваивать enterprise-Laravel-монолиты, а не развивать Nuxt-приложение; стек Nuxt/Prisma списан (ADR-002).

### Вариант Б — Порт Nuxt → Laravel 1:1 (перенос как есть)
- **За:** сохранил бы поведение легаси.
- **Против:** cbook — учебный полигон, а не продукт для сохранения; порт 1:1 воспроизвёл бы известные дыры Nuxt-версии (нет auth, нет серверной валидации, утечка ошибок наружу, небезопасная загрузка файлов) и не дал бы опыта чистой enterprise-раскладки.

### Вариант В — Переписывание с нуля на Laravel ради обучения (выбран)
- **За:** прямо отвечает учебной цели — сборка enterprise-монолита с чистого листа в целевой архитектуре; известные дыры Nuxt-версии **чинятся, а не воспроизводятся**; переиспользование Vue 3/TS на фронте через Inertia; сохраняется общая идея (кулинарная книга) и специфичные переиспользуемые блоки (в первую очередь BVI-панель).
- **Против:** greenfield-скелет с нуля (стоимость старта); коллизия каталога `app/` (Nuxt-фронт → бэкенд Laravel) требует стратегии замещения; объём работы.

> История первичного выбора Nuxt не восстанавливается; здесь фиксируется решение переписать проект на Laravel как учебную инициативу.

## Решение

1. **Переписывание — первая крупная инициатива** проекта; цель — обучение enterprise-паттернам Laravel. Вести педагогично: инкрементальными задачами с пояснением «зачем» каждого паттерна (Task / Repository / Resolver / DTO), обозримыми диффами. Канон исполнения — [`../guides/adr-execution.md`](../guides/adr-execution.md) (оркестратор + субагенты) либо пофично по feature-workflow — по мере уточнения объёма.
2. **Nuxt-код = донор идеи и BVI, а не образец для порта.** Сохраняем только: (а) **общую идею** (кулинарная книга: список / просмотр / добавление с картинкой / удаление рецептов); (б) **специфичные переиспользуемые блоки**, прежде всего **BVI-панель** (доступность для слабовидящих: размер шрифта, темы, синтез речи — клиентская логика, переносится как Inertia/Vue-компонент, от бэкенда не зависит). Всё остальное строится заново. Legacy Nuxt-контур **замещается**, а не сосуществует как параллельный продукт.
3. **Greenfield-старт:** план начинается со скелета Laravel 12 + Sail (стратегия каталога `app/`: замещение Nuxt-фронта на Inertia в `resources/js`), затем бэкенд-скелет слоёв с enforcement изоляции Eloquent, затем доменные срезы снизу-вверх.
4. **Данные:** СУБД — **MySQL 8** (Sail-сервис `mysql`, `:3306`). Схема пишется **заново** под Laravel-миграции (`database/migrations/`) на MySQL 8 — это переписывание, а не перенос Prisma-схемы. Исторические Prisma-миграции неприменимы (см. Gotcha в `../memory.md`).
5. **Файлы:** изображения рецептов — через пакет **`whyme-agency/laravel-media`**, а не через ручной драйвер `s3`. Дисковый бэкенд (локальный/S3) — `(уточнить)`.
6. **Сущности** домена — **Recipe + Ingredient** (`steps` — JSON-поле внутри Recipe, отдельной сущности Step нет; Category в домене нет). `User` появляется **вместе с плановой auth** (в Nuxt-версии auth не было — это закрытие дыры, а не перенос). Создаются в слоистой модели (ADR-003): миграция → Eloquent-модель → Repository → DTO → Task → FormRequest → Controller → Resolver → Inertia-страница → тесты.
7. **Дыры Nuxt-версии — чинить, не воспроизводить:** auth и серверная валидация вводятся сразу, загрузка файлов — безопасная, ошибки наружу не текут.
8. **process-retro (M7)** включается при старте этой инициативы (см. `../memory.md`).

## Последствия

- Legacy Nuxt-код лежит в репозитории как **референс** (донор идеи + BVI) и **замещается** по мере переписывания — параллельного «боевого» контура нет. Боевые креды легаси из `.env` наружу не выносятся, в тестах не используются (тесты — на `.env.testing`).
- Первые задачи — **greenfield-скелет** (Laravel 12 + Sail + пакеты; каталоги слоёв + базовые классы; enforcement изоляции Eloquent через Pest Architecture/deptrac — обычный PHPStan level этого не делает), а не «добавь каталоги в существующий Laravel».
- Создание сущностей подчиняется инвариантам слоёв (ADR-003) и порядку из [`../guides/stack-specifics.md`](../guides/stack-specifics.md).
- Grabli переписывания (схема заново под MySQL 8, медиа через `whyme-agency/laravel-media`, коллизия `app/`) фиксируются в `../memory.md` §Gotchas по мере набивания.
- Открытые вопросы к владельцу: дисковый бэкенд для `whyme-agency/laravel-media` (локальный/S3); нужен ли Cloudflare Tunnel при Sail-стенде; статус CI на `develop`; какие конкретно конвенции из `listvafintess`/`av1` воспроизводить.
