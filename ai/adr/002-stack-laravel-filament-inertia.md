# ADR-002: Целевой стек — Laravel 11 + Filament 3 + Inertia/Vue 3 + TypeScript (Vite)

**Статус:** Принят (зафиксирован при инициализации `ai/`)
**Дата:** 2026-07-28

> Продуктовый decision-ADR. Фиксирует уже принятое при инициализации решение о целевом стеке cbook.
> Обоснование задним числом: описаны реально действовавшие силы и последствия, без выдуманных альтернатив.

## Контекст

cbook — кулинарная книга (рецепты, ингредиенты, шаги, категории, изображения). Текущий код — Nuxt 4 (Vue 3/TS) с Prisma + PostgreSQL (Neon) и MinIO (S3). Решено вести дальнейшую разработку на серверном фреймворке с сильной «батарейной» экосистемой и готовой админкой, сохранив уже знакомый фронтенд-слой (Vue 3 + TypeScript). Требовалось: быстрый CRUD-бэкенд с аутентификацией/авторизацией «из коробки», админ-панель без ручного написания, единый цельный проект (не разнесённый SPA + отдельный API), воспроизводимое локальное окружение.

## Рассмотренные варианты

### Вариант А — Остаться на Nuxt 4 (fullstack Nitro) + Prisma
- **За:** код уже написан; не нужна миграция; единый язык (TS) на всех слоях.
- **Против:** админку и авторизацию/политики надо строить руками; серверная экосистема тоньше, чем у зрелого backend-фреймворка; выбран отход от этого пути (см. ADR-006).

### Вариант Б — Laravel 11 + Filament 3 + Inertia/Vue 3 + TS (выбран)
- **За:** Laravel даёт auth, очереди, валидацию, миграции, файловые драйверы (S3) из коробки; Filament 3 — готовая админ-панель на политиках доступа; Inertia сохраняет фронт на Vue 3 + TypeScript без отдельного REST-клиента (сервер как источник данных); Laravel Sail — воспроизводимое Docker-окружение.
- **Против:** brownfield-миграция с Nuxt (стоимость переноса — см. ADR-006); два языка/тулчейна (PHP + TS); PHP-инструменты идут через контейнеры Sail.

## Решение

Целевой стек cbook, в котором ведётся разработка:

1. **Backend:** Laravel 11 (PHP 8.3), слоистая архитектура (детали — ADR-003).
2. **Админка:** Filament 3, панель `/admin`; Resource'ы без бизнес-логики, делегируют в сервисы.
3. **Frontend:** Inertia.js + Vue 3 + TypeScript, сборка Vite; данные приходят props'ами Inertia (без отдельного публичного API-клиента).
4. **Хранение:** PostgreSQL (преемственность с Neon; в Sail — сервис `pgsql`); файлы (изображения рецептов) — драйвер `s3`/MinIO. Кэш/очереди — Redis.
5. **Локальное окружение:** Laravel Sail (Docker). Тесты — Pest/PHPUnit; типы — PHPStan (Larastan) + `vue-tsc`; линт/формат — Laravel Pint (+ ESLint на фронте).

## Последствия

- Команды/версии стека — единый источник в [`../guides/stack-specifics.md`](../guides/stack-specifics.md); документация значения из скриптов не дублирует.
- Минимальный набор гейтов проекта: тесты + typecheck + lint (Pint); тяжёлые прогоны сериализуются через `gate.sh`.
- Появляется brownfield-миграция Nuxt → Laravel как первая крупная инициатива (ADR-006); до её завершения legacy-контур (Nuxt/Prisma/Neon/MinIO/Cloudflare Tunnel) существует параллельно.
- Издержка: два тулчейна (PHP-через-Sail и Node/pnpm), PHP-инструменты доступны только при поднятых контейнерах.
- Открытый вопрос: финальный выбор СУБД (Postgres по умолчанию, преемственность с Neon) — подтвердить у владельца.
