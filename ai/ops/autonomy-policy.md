# Политика автономии агентов

Определяет, что агенты делают без участия пользователя, что — с уведомлением, и где участие
человека обязательно. Дополняет `security-rails.md` (физические запреты) и `../guides/`
(процессные гейты). Введена 2026-07-31 по решению владельца.

## Принцип

Безопасность автономии обеспечивается **не доверием к агенту, а эшелонами**:

1. **Негативные рельсы** (см. `security-rails.md`): deny-правила, PreToolUse-клетка,
   guard-write, git-хуки, pushurl=DISABLED, TTY-гейт `deliver.sh`. Их автономия не ослабляет.
2. **Самопроверка процесса** (см. `../guides/`): спека → тройная проверка вторым агентом →
   гейты (pest/phpstan/pint/build) → живая приёмка → обязательное адверсариальное
   коммит-ревью независимым агентом (ADR-010) → fix-forward → повторное ревью.
3. **Permission-режим `auto`** (`.claude/settings.local.json`): LLM-классификатор одобряет
   рутину без промпта; `ask`-правила форсируют вопрос пользователю на критическом
   в любом режиме; `deny` — физический блок поверх всего.

## Три уровня действий

### Агент решает сам (молча, по канону гайдов)
Тесты и гейты качества; скрипты workspace (`sync/status/coord/task/gate/commit/ai-commit`);
sail/docker-стенды на изолированных портах из брони; composer/pnpm/artisan;
коммиты в task-worktree через `commit.sh`; коммиты артефактов `ai/` через `ai-commit.sh`;
делегирование субагентам (модели — по правилу §0 architecture.md); fix-forward по
блокерам коммит-ревью (1 итерация).

### Агент решает и отчитывается (пользователь читает постфактум)
Вердикты ревью (PASS/FAIL) и их закрытие; отклонения от спеки (документируются в impl.md,
оцениваются ревьюером); границы между фичами в рамках утверждённого скоупа.

### Только пользователь (агенту — `ask`-промпт или физический блок)
- **Скоуп**: какие фичи делаем, стратегия исправления косяков — через `AskUserQuestion`.
- **Наружу**: `deliver.sh` (TTY-гейт + `ask`), `ai-push.sh` (`ask`), создание MR.
- **Обвязка**: правки `githooks/`, `.claude/settings.json`, стоп-словаря, allow-паттернов
  (guard-write блокирует агента физически).
- **Разрушительное**: `rm -rf` (`ask`), любые операции вне канона гайдов.

### Эскалация к пользователю по исключению
Ревью-FAIL, не закрытый одним fix-forward; конфликт контрактов между спеками;
подозрение на инцидент гигиены §8; недоступность инфраструктуры (Docker/сеть),
блокирующая гейты.

## Уведомления

`inputNeededNotifEnabled: true` — push-уведомление, когда агент ждёт ввода
(`ask`-промпт или вопрос по скоупу). Пользователь не дежурит у терминала: агенты
работают фоном, оркестратор зовёт один раз на фичу — на доставку.

## Sandbox (отложено)

OS-песочница (Seatbelt) с сетевым белым списком — целевой следующий эшелон
(см. `security-rails.md`, финальная секция), но несовместима с Docker-гейтами
(Sail). Вернуться при переходе на devcontainer-контур.
